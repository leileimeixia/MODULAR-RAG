一、 协议与工具层
MCP (Model Context Protocol)
通俗解释：大模型与外部世界（如本地文件系统、数据库）沟通的“通用外交协议”。
结合文件：大模型本身不能直接看你电脑里的 data/documents 文件夹，必须通过 MCP 协议规定的标准格式来发送请求和接收数据。
Tool (工具)
通俗解释：大模型可以调用的“插件”或“技能”。
结合文件：本文件实现的 list_collections 就是一个 Tool，相当于给大模型配备了一个“查看本地知识库目录”的技能。
Collection (文档集合)
通俗解释：知识库里的“分类文件夹”或“档案柜”。
结合文件：在 data/documents 目录下，每一个子文件夹（如 company_policies）就是一个 Collection。用户可以先用本工具看看有哪些柜子，再去特定柜子里找文件。
二、 参数与执行层
Schema (模式/规范)
结合文件：文件中的 LIST_COLLECTIONS_SCHEMA 规定了调用 list_collections 时不需要任何额外属性（"additionalProperties": False）。大模型在调用前会先看 Schema，确保自己传的参数格式合法。
Arguments (参数)
通俗解释：调用工具时传入的“具体指令”或“点菜单”。
结合文件：当大模型决定使用 list_collections 时，会传入一个 arguments 字典。虽然这个工具不需要额外参数（传空字典 {} 即可），但如果是查询工具，arguments 里就会包含 {"query": "公司报销标准"} 这样的具体指令。
Handler (处理函数)
通俗解释：工具的“幕后执行者”或“真正干活的工人”。
结合文件：大模型填好参数（arguments）后，MCP 服务器会根据指引，找到对应的 handler（即 list_collections() 函数）去真正执行扫描目录的代码逻辑。
ToolSpec (工具规范)
通俗解释：工具的“完整身份证”或“档案袋”。
结合文件：文件中的 tool_spec() 函数返回一个 ToolSpec 对象，它把工具的名字、描述、schema（说明书）和 handler（执行者）打包在一起，统一交给 MCP 服务器进行注册。
三、 数据返回层
Content (内容)
通俗解释：给“人或大模型”看的自然语言总结报告。
结合文件：工具返回的结果中，content 是一段排版好的纯文本（如 - company_policies: documents=5...），方便大模型直接阅读并转化为自然语言回答用户。
StructuredContent (结构化内容)
通俗解释：给“程序或前端 UI”看的结构化数据（如 JSON 表格）。
结合文件：返回结果中的 structuredContent 包含了具体的集合名、路径、文件数等字典数据，方便前端代码直接拿去渲染表格、做过滤器或进行下一步的逻辑处理。
💡 核心概念串联总结
大模型通过 MCP 协议发现了一个叫 list_collections 的 Tool。它先阅读了 Schema，知道不需要传特殊参数，于是发送了一个空的 Arguments。MCP 服务器收到请求后，找到对应的 Handler 函数去执行扫描。最后，Handler 把结果分成两份：一份易读的 Content 给大模型看，一份结构化的 StructuredContent 给程序用。
